# แล็บ: โมเดลเร็วกับโมเดลฉลาด

- บท: `core-01`
- เวลา: 10–15 นาที
- แทร็กเริ่มต้น: Cursor — ดูขั้นตอนเพิ่มใน [tracks/cursor.yaml](../tracks/cursor.yaml)

## โจทย์

ใช้พรอมต์เดียวกันกับโมเดลสองระดับในเครื่องมือที่เลือก แล้วตัดสินว่างานแบบนี้ควรใช้ตัวไหนเป็นค่าเริ่มต้น

พรอมต์บังคับ:

```text
มีฟังก์ชันคิดราคาสินค้าหลังส่วนลด
กฎคือ ซื้อครบ 3 ชิ้นลด 10% และไม่ลดซ้ำกับคูปอง
จงเสนอเทสสามเคส
แต่ละเคสบอกอินพุต ค่าที่คาด และเหตุผลสั้นๆ
อย่าเขียนโค้ดทั้งไฟล์
```

## ขั้นตอน

1. ส่งพรอมต์ด้วยโมเดลที่ทีมเรียกว่าเร็วหรือถูก
2. ส่งพรอมต์เดิมด้วยโมเดลที่คิดนานหรือฉลาดกว่า ในเธรดใหม่
3. จดเวลาโดยประมาณ ความยาวคำตอบ และการยอมรับกรณีพิเศษ เช่น ของแถมหรือส่วนลดทศนิยม
4. เลือกตัวตั้งต้นสำหรับงานออกแบบเทสแบบนี้

ถ้ายังไม่มีโปรเจกต์ของตัวเอง ให้ใช้โจทย์ส่วนลดนี้โดยไม่ต้องมีโค้ดจริง

## เกณฑ์ผ่าน

ผ่านเมื่อมีบันทึกครบสี่ช่องนี้:

| ช่อง | ต้องมี |
| --- | --- |
| โมเดล A / B | ชื่อหรือป้ายที่เห็นในเครื่องมือ |
| เวลา | ช้า/เร็วกว่ากันชัดเจน หรือจับเวลาหยาบได้ |
| คุณภาพ | เทสของใครครอบคลุมกรณีซ้ำซ้อนกว่า |
| ค่าเริ่มต้น | เลือกหนึ่งตัวพร้อมเหตุผลหนึ่งประโยค |

## เฉลยแนวทาง

ไม่มีคำตอบโมเดลเดียวที่ถูกทุกทีม คำตอบที่ถูกคือการเลือกตามราคาของความผิดพลาด

- ถ้าต้องการไอเดียเทสเร็วๆ เพื่อเริ่มเขียนเอง โมเดลเร็วพอ
- ถ้าเทสจะถูกใช้ตัดสินรับงาน โมเดลที่ตั้งข้อแม้และกรณีขอบได้ดีกว่าคุ้มกว่า
- ถ้าคำตอบของโมเดลฉลาดยาวแต่ไม่เพิ่มเคสที่มีประโยชน์ ให้ถอยกลับไปใช้โมเดลเร็ว

ตัวอย่างเคสที่ควรโผล่ในคำตอบที่ดี: ซื้อ 2 ชิ้นไม่ลด, ซื้อ 3 ชิ้นลด 10%, มีคูปองแล้วต้องไม่ลดซ้ำ
