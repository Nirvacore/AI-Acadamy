# แล็บ: เทียบพรอมต์สั้นกับพรอมต์ยาว

- บท: `core-03`
- เวลา: 10–15 นาที
- แทร็กเริ่มต้น: Cursor — ดูขั้นตอนเพิ่มใน [tracks/cursor.yaml](../tracks/cursor.yaml)

## โจทย์

วัดว่าขนาดอินพุตเปลี่ยนต้นทุนและคุณภาพอย่างไร โดยถามคำถามเดียวกันสองแบบ

คำถามร่วม:

```text
สรุปกฎคิดส่วนลดในสามข้อ
แล้วบอกว่าเทสไหนขาดอยู่หนึ่งเคส
```

## ขั้นตอน

1. แชทสั้น: ส่งเฉพาะคำถามร่วม และอ้างไฟล์ราคาไฟล์เดียวถ้ามี
2. แชทยาว: วางหรือแนบไฟล์ที่ไม่เกี่ยวอีกอย่างน้อยสองไฟล์ หรือวางล็อกยาว แล้วส่งคำถามเดิม
3. ดู usage ถ้ามี ถ้าไม่มีให้คะแนนขนาดอินพุตเป็นเล็ก/กลาง/ใหญ่
4. เทียบว่าคำตอบยาวขึ้น มีประเด็นนอกเรื่อง หรือดีขึ้นจริงหรือไม่

## เกณฑ์ผ่าน

ผ่านเมื่อตารางนี้เต็ม:

| รายการ | แชทสั้น | แชทยาว |
| --- | --- | --- |
| สิ่งที่ส่งไป | | |
| ขนาดอินพุตโดยประมาณ | | |
| คำตอบมีสามข้อกฎหรือไม่ | | |
| มีเนื้อหานอกเรื่องหรือไม่ | | |
| จะใช้แบบไหนในงานจริง | | |

## เฉลยแนวทาง

แชทสั้นมักพอสำหรับคำถามสรุปกฎ แชทยาวมักแพงกว่าโดยไม่ได้เพิ่มเคสเทสที่มีประโยชน์

คำตอบที่ดีของแล็บนี้คือเลือกแชทสั้นเป็นค่าเริ่มต้น และแนบไฟล์เพิ่มเฉพาะตอนคำตอบสั้นผิดหรือไม่ครบ

ถ้าแชทยาวจับบั๊กที่แชทสั้นพลาด ให้เขียนไว้ว่าไฟล์พิเศษไฟล์ไหนเป็นตัวตัดสิน แล้วยกไฟล์อื่นออกในรอบถัดไป
