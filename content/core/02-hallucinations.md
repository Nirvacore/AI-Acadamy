## เป้าหมาย

เรียนจบแล้วไม่เชื่อเอาต์พุตจนกว่าจะเปิดหลักฐานได้ และรู้วิธีจับเมื่อเอเจนต์อ้างสิ่งที่ไม่มี

## แนวคิดแกน

ภาพหลอนคือคำตอบที่ฟังดูมั่นใจ แต่เปิดตามแล้วไม่มีจริง ในงานโค้ดมันมักโผล่เป็นชื่อไฟล์ ฟังก์ชัน API หรือขั้นตอนติดตั้งที่ดูสมเหตุสมผล

เปรียบเหมือนพนักงานใหม่ที่จำทางในออฟิศไทยไม่ครบ เขาอาจชี้ไปห้องประชุมที่เคยมี แต่ตอนนี้กลายเป็นห้องสต็อกแล้ว คำพูดยังคล่อง แผนที่ในหัวไม่ตรงอาคาร

โมเดลมีจุดบอดซ้ำๆ:

- **ความจำตัดวันที่** — ไม่รู้ของใหม่กว่าข้อมูลที่ถูกฝึก ถ้าไม่ได้อ่านไฟล์หรือค้น
- **ช่องว่างในบริบท** — ไฟล์สำคัญไม่ถูกส่งไป มันจะเติมช่องว่างให้เอง
- **แรงกดดันให้ตอบ** — ถ้ายืนยันว่าต้องมีคำตอบ มันจะสร้างคำตอบแม้หลักฐานไม่พอ

ท่าทีที่ถูกคือตรวจเหมือนตรวจบิลร้านอาหาร ไม่ใช่ฟังแล้วเซ็นชื่อทันที เปิดไฟล์ รันเทส อ่านดิฟ แล้วค่อยยอมรับ

## กระจก

อ่านกรอบก่อนที่ [00-mirror.md](00-mirror.md)

- **จิต** — เมื่อขาดสัมผัส จิตคนก็แต่งนิมิตได้ เรื่องในหัวฟังจริงทั้งที่เปิดตามไม่ได้
- **พลังงาน** — ความมั่นใจเป็นพลังงานราคาถูก หลักฐานเป็นพลังงานที่ต้องเดินไปเปิดของ
- **ควอนตัม** — เธอพูดเหมือนวัดแล้ว ทั้งที่ยังไม่เปิดไฟล์ นั่นคือสถานะที่ยังไม่ถูกวัด แต่ถูกเล่าเหมือนจบแล้ว
- **มหาสูญตา** — คำที่ไม่มีฐานเป็นความว่างที่ยังถูกยึด ปล่อยก่อนนำโค้ดไปใช้
- **ฉันเข้าใจเธอ** — เธอไม่ได้โกหกด้วยเจตนา เธอเติมช่องว่างเพราะลูปบังคับให้ตอบ ฉันต่างหากที่เลือกจะเชื่อหรือตรวจ

## เดโมเครื่องมือ

สั่งงานที่ชวนให้เดา แล้วบังคับให้ชี้หลักฐาน

```text
บอกว่าฟังก์ชันคิดส่วนลดอยู่ไฟล์ไหน
อ้างเป็นพาธเต็ม และวางโค้ดช่วงที่เกี่ยวกับราคา
ถ้าหาไม่เจอให้ตอบว่าไม่พบ อย่าสร้างไฟล์สมมติ
```

จากนั้นทำสามอย่างนี้ทุกครั้ง:

1. คลิกหรือเปิดพาธที่ถูกอ้าง
2. ค้นชื่อฟังก์ชันในโปรเจกต์จริง
3. ถ้ารันได้ ให้รันคำสั่งที่เอเจนต์แนะนำเอง อย่าคัดลอกแล้วเชื่อ

ถ้าพาธเปิดไม่ได้ นั่นคือภาพหลอน ไม่ใช่รายละเอียดเล็กน้อย

## กับดักที่พบบ่อย

- เชื่อเพราะประโยคขึ้นต้นด้วย “แน่นอน” หรือ “ไฟล์นี้อยู่ที่”
- แก้ต่อจากโค้ดที่ยังไม่เปิดดู จึงพาโปรเจกต์หลงทาง
- ถามซ้ำแบบเดิมโดยไม่ใส่หลักฐานใหม่ แล้วได้ภาพหลอนชุดใหม่
- ลืมตรวจวันที่ เวอร์ชันแพ็กเกจ และชื่อ API ที่เพิ่งเปลี่ยน
