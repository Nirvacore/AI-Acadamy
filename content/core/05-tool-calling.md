## เป้าหมาย

เรียนจบแล้วมองเครื่องมือเป็นความสามารถของเอเจนต์ และบังคับให้ค้นหรือรันคำสั่งแทนการเดา

## แนวคิดแกน

โมเดลอย่างเดียวอ่านได้เฉพาะสิ่งที่อยู่ในคอนเท็กซ์ เครื่องมือทำให้มันแตะโลกจริงได้ เช่น ค้นไฟล์ รันเทส เปิดเบราว์เซอร์ หรือเรียกบริการผ่าน MCP

เปรียบเหมือนแม่ครัวที่จำสูตรได้ แต่ถ้าไม่มีทัพพี เตา และตู้เย็น เธอทำได้แค่เล่าเมนู การเรียกเครื่องมือคือการยื่นของจริงให้ลงมือ ไม่ใช่ให้พูดอย่างเดียว

เครื่องมือมีราคา:

- แต่ละครั้งที่เรียก จะอ่านผลกลับเข้าคอนเท็กซ์
- ผลยาว เช่น ล็อกเทสทั้งก้อน ทำให้รอบถัดไปแพงและวุ่น
- เครื่องมือผิดใบ พาเอเจนต์มั่นใจในข้อมูลผิด

เพราะงั้นอย่าเปิดทุกเครื่องมือตั้งแต่ต้น ให้เปิดเท่าที่งานต้องการ แล้วสั่งให้ใช้เครื่องมือเมื่อคำตอบต้องอิงสถานะจริงของโปรเจกต์

## เดโมเครื่องมือ

ใช้โจทย์ที่เดาแล้วพลาดได้ง่าย เช่น หาชื่อฟังก์ชันคิดราคา

พรอมต์ที่ห้ามเดา:

```text
หาฟังก์ชันที่คำนวณราคาสุทธิหลังส่วนลด
ต้องใช้เครื่องมือค้นในโปรเจกต์
ตอบเป็นพาธไฟล์ ชื่อฟังก์ชัน และบรรทัดโดยประมาณ
ห้ามสร้างชื่อใหม่ถ้าค้นไม่เจอ
```

สิ่งที่ควรเห็นคือลำดับ roughly แบบนี้: ค้นหรือลิสต์ไฟล์ → อ่านไฟล์ที่ตรง → ตอบพร้อมหลักฐาน ไม่ใช่ตอบชื่อฟังก์ชันในประโยคแรกโดยไม่อ่านอะไร

ถ้าแทร็กมี MCP ให้ลองเครื่องมือที่อ่านของจริง เช่น สถานะบิลด์หรือเอกสารภายใน แล้วยังคงตรวจผลเอง

## กับดักที่พบบ่อย

- ปล่อยให้เอเจนต์ตอบจากความจำของโมเดล ทั้งที่ไฟล์อยู่ในเครื่อง
- ให้รันคำสั่งทำลายข้อมูลโดยไม่อ่านคำสั่งก่อน
- เปิด MCP หลายตัวจนเอเจนต์เลือกเครื่องมือผิด
- ลืมว่าผลเครื่องมือกินโทเคน แล้วส่งล็อกทั้งไฟล์กลับเข้าแชท
