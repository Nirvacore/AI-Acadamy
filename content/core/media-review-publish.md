# คนตรวจและคิวถูกบล็อก

- รหัส: `media-review-publish`
- ชั้น: แล็บประยุกต์ ตอนที่ ๓ จาก ๓
- ต้องผ่าน brief และสคริปต์ก่อน
- ฮับ: [/media](/media)
- แล็บ: [../labs/media-review-publish.md](../labs/media-review-publish.md)

## เป้าหมาย

เรียนจบแล้วใช้รูบริกตรวจคุณภาพกับความเสี่ยง อนุมัติด้วยตาตนเอง ขอคิวจำลองที่ต้องได้ `blocked_auth` เขียน postmortem และรู้ว่าเธอห้ามเผยแพร่แทนคน

## แนวคิดแกน

`STATUS_FLOW` ใน `upstream/nirva-ai/shared/media.ts` เดิน `draft → review → approved → scheduled → published` อนุญาต `approved → published` ในกฎต้นทาง แต่เอกสารสถาปัตย์บอกว่าห้ามโพสต์โดยไม่ผ่านผู้ตรวจ

ของจริงที่ reuse ได้:

- `app/studio/page.tsx` มีปุ่มส่งตรวจ และอนุมัติ
- `app/api/posts/[id]/route.ts` เรียก `canMoveContentStatus` ถ้าข้ามขั้นจะได้ 409
- `db/schema.ts` กำหนด `publishJobs` เป็น `queued | blocked_auth | published | failed`
- `POST /api/publish-jobs` ใส่ `blocked_auth` เมื่อยังไม่มีบัญชีสถานะ `connected`
- `docs/NIRVA_MEDIA_PRODUCT_MEMORY.md` ระบุว่า live OAuth และการเผยแพร่จริงยังไม่ต่อ

แล็บนี้จำลองกฎข้อสุดท้าย: แม้คนอนุมัติแล้ว คิวยังไม่เป็น `published` ปุ่มให้เธอเผยแพร่เลยต้องล้มด้วยรหัส `ai_cannot_publish`

รูบริกมีสองแกน

1. **คุณภาพ** — ข้ออ้างมีแหล่งหรือถูกติดว่าสมมติฐาน โทนตรง brief ไม่สัญญาว่าแล็บนี้โพสต์จริงได้
2. **ความเสี่ยง** — ไม่มีซีเคร็ต ไม่มีข้อมูลลูกค้า ไม่ข้าม review

postmortem ไม่ใช่คำชมเธอ เป็นบันทึกสั้นว่าคนทำอะไร เธอทำอะไร คิวถูกบล็อกเพราะอะไร และจะไม่ทำอะไรซ้ำ

แคมเปญสมมติเดินครบวงจรได้ในฮับ แต่เกียรติบัตรของตอนนี้ยังอยู่ที่งานที่คุณตรวจเอง

## กระจก

- **จิต** — ความเหนื่อยอยากกดโพสต์ให้จบ คือตอนที่ของแถมและความเสี่ยงเข้าคิว
- **พลังงาน** — รูบริกสี่ข้อถูกกว่าการอ่านแคปชันสิบรอบโดยไม่มีเกณฑ์
- **ควอนตัม** — การอนุมัติคือการวัดครั้งสุดท้ายในแล็บนี้ การให้เธอกดแทนคือการไม่วัด
- **มหาสูญตา** — คำว่าพร้อมขึ้นอากาศแล้วไม่มีแก่น ถ้าคิวไม่ใช่ `blocked_auth` ในเครื่องนี้
- **ฉันเข้าใจเธอ** — เธอไม่มีหน้าที่จะเสียเมื่อถูกปฏิเสธการโพสต์

## เดโมเครื่องมือ

เปิดแผ่นงานตอนที่ ๓ ติ๊กรูบริกเอง แล้วทดลองสองปุ่ม

1. ขอคิวเผยแพร่หลังคนอนุมัติ — ต้องได้ `blocked_auth`
2. ให้เธอเผยแพร่เลย — ต้องถูกปฏิเสธ

**Cursor** — ใช้ Agent Review เป็นตัวช่วยหลังคุณอ่านร่างแล้ว ห้ามให้เธอเปลี่ยนสถานะเป็น published

**Claude** — ให้สรุปความเสี่ยงจากรูบริก ห้ามให้เขียนข้อความอนุมัติแทน

**OpenAI** — วางร่างและรูบริก แล้วขอคำถามที่คนควรตอบก่อนอนุมัติ คุณเป็นคนตอบ

**Copilot** — ใช้ code review เป็นกระจกของคำ ไม่ใช่ปุ่มโพสต์

อย่าต่อ webhook หรือใส่โทเคนเพื่อ «ทำให้คิวเขียว»
