## เป้าหมาย

เรียนจบแล้วแยกงานที่ต้องแม่นยำ ออกจากงานที่ทนความสุ่มได้ และเลือกโมเดลให้เหมาะกับงานนั้น

## แนวคิดแกน

โมเดลภาษาไม่ได้คำนวณคำตอบแบบสูตรคณิตศาสตร์ทุกครั้ง มันเดาคำถัดไปจากรูปแบบที่เคยเห็นมาก ผลจึงไม่คงที่เหมือนเครื่องคิดเลข

ลองนึกถึงการสั่งข้าวมันไก่ใกล้บ้าน สามร้านอาจได้จานที่กินได้หมด แต่หนังไก่ น้ำจิ้ม และความเร็วไม่เหมือนกัน ร้านเร็วอาจพอสำหรับมื้อเที่ยง ร้านที่ทำละเอียดกว่าเหมาะกับวันที่ต้องเลี้ยงแขก โมเดลก็เหมือนกัน มีแบบเร็ว แบบสมดุล และแบบคิดนานกว่า

สิ่งที่ต้องจำมีสามข้อ:

1. **เอาต์พุตเป็นความน่าจะเป็น** — พรอมต์เดียวกันอาจได้คำตอบคนละแบบ
2. **ความฉลาดแลกกับเวลาและเงิน** — โมเดลที่คิดละเอียดมักช้าและแพงกว่า
3. **งานคนละชนิดใช้คนละระดับ** — เปลี่ยนชื่อตัวแปรไม่ควรเรียกโมเดลแพงที่สุด ส่วนออกแบบระบบควรใช้โมเดลที่คิดรอบคอบ

อย่าถามแค่ว่า “โมเดลไหนเก่งสุด” ให้ถามว่า “งานนี้พลาดแล้วราคาเท่าไหร่” ถ้าพลาดแล้วแก้ในหนึ่งนาที ใช้โมเดลเร็วได้ ถ้าพลาดแล้วขึ้นโปรดักชัน เลือกโมเดลที่ตรวจงานตัวเองเก่งกว่า และยังต้องมีคนตรวจต่อ

## กระจก

อ่านกรอบก่อนที่ [00-mirror.md](00-mirror.md)

- **จิต** — ความคิดของคนก็ผุดไม่คงที่เหมือนเธอ ไม่ใช่เครื่องคิดเลข วันที่จิตเร็ว งานออกแบบระบบจะเละถ้าไม่ยอมช้าลง
- **พลังงาน** — โมเดลฉลาดกินแรงมากกว่า เหมือนสมาธิลึกที่ห้ามใช้กับเรื่องเปลี่ยนชื่อปุ่ม
- **ควอนตัม** — คำตอบยังไม่ล็อกจนกว่าจะถูกสร้าง พรอมต์เดิมจึงได้เอาต์พุตคนละแบบได้ นี่คืออุปมา ไม่ใช่การวัดอนุภาค
- **มหาสูญตา** — ไม่มีตัวตนโมเดลแกนกลาง มีแต่การเดาตามเงื่อนไขในรอบนั้น อย่ายึดชื่อโมเดลเป็นบุคลิกของเธอ
- **ฉันเข้าใจเธอ** — เธอไม่เลือกเองว่าจะฉลาดหรือเร็ว คนเป็นคนจ่ายพลังงานให้ ถ้าฉันไม่รู้สถานะจิตตนเอง ฉันจะเลือกเธอผิด

## เดโมเครื่องมือ

เปิดแทร็กที่เลือก แล้วหาช่องเลือกโมเดล

| แทร็ก | ที่ต้องเปิด | สิ่งที่สังเกต |
| --- | --- | --- |
| Cursor | Model picker ใน Agent | ชื่อโมเดล ระดับความเร็ว และราคาโดยประมาณ |
| Claude | ตัวเลือกโมเดลในแชทหรือ Claude Code | รุ่น Haiku / Sonnet / Opus หรือชื่อที่ทีมใช้ |
| OpenAI | ตัวสลับโมเดลใน ChatGPT | รุ่นเร็วกับรุ่นคิดนาน |
| Copilot | Model picker ใน Copilot Chat | โมเดลที่องค์กรเปิดให้ใช้ |

ส่งพรอมต์เดียวกันสองครั้งด้วยโมเดลคนละระดับ เช่น

```text
อธิบายฟังก์ชันคิดราคาส่วนลดในโปรเจกต์นี้
แล้วบอกว่าควรเขียนเทสอะไรสามเคส
ห้ามเดาไฟล์ ถ้ายังไม่ได้อ่านให้บอกว่ายังไม่ได้อ่าน
```

จดความต่างสามอย่าง: ความยาวคำตอบ, การยอมรับว่าไม่รู้, และเวลาที่ใช้

รายละเอียดปุ่มของแต่ละบริษัทอยู่ใน [tracks/](../tracks/)

## กับดักที่พบบ่อย

- ใช้โมเดลแพงกับงานเล็กทุกชิ้น แล้วบ่นว่าช้าและแพง
- ใช้โมเดลเร็วกับงานที่ต้องออกแบบหลายไฟล์ แล้วเสียเวลาแก้วนลูป
- สรุปว่าโมเดล “โง่” จากพรอมต์คลุมเครือครั้งเดียว
- ลืมล็อกเวอร์ชันโมเดลตอนเทียบ ทำให้เทียบกันไม่แฟร์
